# Physical device verification worksheet

Owner currently has Android devices only. The S24 single-device smoke and S24/tablet Nearby rows below have physical evidence. Other communication, range, battery and lifecycle rows remain **NOT RUN**. Do not mark a browser viewport emulation as Android hardware verification.

Measured devices: **Samsung Galaxy S24 / SM-S921B** and **Samsung tablet / SM-X510**, both Android 16/API 36, security patch 2026-08-05. S24 Play services is 26.36.35 and Chrome package 154.0.8037.92; tablet Play services is 26.34.36 and Chrome package 154.0.8037.57. Both reported Direct/Aware features and current Aware availability. The S24's Direct discovery counted one peer after ten seconds; no Direct/Aware data connection was attempted. See [the single-device smoke](benchmarks/samsung-s24-smoke.json) and [two-device Nearby record](benchmarks/samsung-s24-tablet-nearby.json). This evidence does not establish broader Android or interoperable Aware compatibility.

For this S24 test camera/microphone denial and later grant, Android Nearby devices permissions for native probes, Samsung battery saver and app sleep settings, foreground/background and screen lock. Any OS settings change is a user action through the normal settings UI. Saathi must explain a denial and retain local work, never silently change radios or battery policy.

Use operator HTTPS for the PWA; `http://192.168…` is not a production or secure-origin substitute. Preload/prepare both devices online, retain the secure origin, then disconnect WAN/cellular while leaving the local network available. Keep a third carrier device for the multi-hop test when possible.
