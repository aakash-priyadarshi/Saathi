# Threat model

| Threat                                                          | Implemented control                                                                                                                                      | Remaining operational work                                                        |
| --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Public user impersonates a verified volunteer                   | Database-derived sessions, approved memberships, RBAC on every write                                                                                     | Independent authorization review and admin access policy                          |
| Volunteer edits another organization's request                  | Server-side organization checks and creator/coordinator edit rules                                                                                       | Periodic membership audits                                                        |
| Two donors claim the last units                                 | Request row locks, quantity constraints, transactional idempotency                                                                                       | Stress/load test production sizing                                                |
| Retry double-counts supplies                                    | Durable UUID idempotency records and transaction-scoped locks                                                                                            | Retention and encrypted backup policies                                           |
| Old shared screenshot attracts excess supplies                  | Permanent canonical pages, verification, explicit closed notices                                                                                         | Community guidance to share canonical links                                       |
| Guessed/reused private contribution link                        | 256-bit tokens, stored hashes, private/no-referrer/no-store pages                                                                                        | Token rotation/recovery and log/analytics discipline                              |
| Compromised volunteer account                                   | Sessions revoke, suspension, content hiding, audit history                                                                                               | Self-service MFA, recovery, encrypted TOTP storage and incident playbooks         |
| Malicious file or location metadata                             | Decode limits, signature inspection, production scanner, Sharp/FFmpeg normalization                                                                      | Sandbox/isolate processors; independent file-security review                      |
| Personal information visible inside media                       | Moderation before public media access and publishing guidance                                                                                            | Face protection; trained moderators; periodic review                              |
| Provider outage loses confirmed delivery                        | Delivery/outbox/audit committed together; email retries separately                                                                                       | Monitor retry backlog and provider credentials                                    |
| Redis outage bypasses allocation or expiry                      | PostgreSQL allocation locks; lazy/periodic database expiry                                                                                               | Alerting and worker failover drills                                               |
| Database/storage mismatch during moderation                     | Feed needs approved DB state; hide deletes derivatives                                                                                                   | Durable media reconciliation job; storage-only orphan cleanup; cache invalidation |
| Tampered audit history                                          | Database append-only triggers, no normal-user audit mutation APIs                                                                                        | Dedicated restricted application role and external audit export                   |
| API spam and credential attacks                                 | Strict validation, local rate limiter, DB login lockouts                                                                                                 | Trusted-ingress distributed per-client throttling, traffic budgets                |
| Offline forgery, replay, stale reopening                        | Canonical P-256 original-author signatures, registered/revocable keys, current org approval, expiry/hop bounds, durable deduplication and version checks | Independent protocol review and physical adversarial tests                        |
| Carrier changes authorship or invents publication               | Original envelope preserved; server-signed receipts bound to event hashes and pinned keys; nearby delivery differs from publication                      | Receipt-key backup, rotation/keyring migration and compromise playbook            |
| Nearby transfer consumes data or captures media without consent | Explicit public-event carrier opt-in, matching pairing codes, attachment acceptance, accepted calls, no cloud media relay/recording                      | Physical permission tests and native-platform proofs                              |
| Browser eviction or device compromise loses/exposes local work  | Durable writes before acknowledgements, retention request, exports, nonextractable keys and explicit clear/logout                                        | Device security, independent origin security review and user backups              |
| Stale offline quantities prompt excess purchases                | Saved-information age, last-known wording, current-connection requirement for donor mutations                                                            | Field usability tests and operator guidance                                       |

Trust boundaries include the browser/API boundary, org membership, server/storage, local browser profile, confirmed nearby peer session, offline author/carrier separation and app/DB-admin access. The central database remains authoritative. Public storage is intentionally public only for sanitized approved media. Provider credentials and private objects belong to the operator. The system does not promise anonymity against lawful investigation.
